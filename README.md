# Практическое задание №1 — вариант №19

## Тема

Эмулятор языка оболочки ОС, максимально приближенный по поведению к командной строке UNIX-подобной ОС.

Проект реализован на **Python 3** и закрывает требования этапов 1–5: REPL, конфигурация, виртуальная файловая система из ZIP, основные и дополнительные команды, стартовые скрипты, обработка ошибок и набор сценариев тестирования.

## Быстрый запуск

Требуется Python 3.10+.

```bash
bash run.sh --config config/default.json
```

Запуск с явными аргументами:

```bash
bash run.sh \
  --config config/default.json \
  --vfs vfs/sample_vfs.zip \
  --script tests/full_demo.txt
```

Параметры командной строки имеют приоритет над значениями из JSON.

## Этап 1. REPL

Реализован консольный интерфейс.

Приглашение формируется из реальных данных ОС:

```text
username@hostname:~$
```

Для каталогов VFS вместо `~` отображается текущий виртуальный путь.

Разбор команд выполняется через `shlex.split`, поэтому аргументы в кавычках поддерживаются:

```text
touch "file with spaces.txt"
```

Неизвестные команды и неверные аргументы приводят к понятным сообщениям об ошибках, но не завершают эмулятор.

На первом этапе присутствуют команды `ls`, `cd` и `exit`.

## Этап 2. Конфигурация

Поддерживаются аргументы:

```text
--vfs PATH
--script PATH
--config PATH
```

JSON-конфигурация:

```json
{
  "vfs_path": "vfs/sample_vfs.zip",
  "startup_script": "tests/full_demo.txt"
}
```

Если одно и то же значение задано и в JSON, и в командной строке, значение командной строки имеет приоритет.

При запуске выводятся итоговые значения параметров:

```text
Resolved parameters:
  config_path    = 'config/default.json'
  vfs_path       = 'vfs/sample_vfs.zip'
  startup_script = 'tests/full_demo.txt'
```

Стартовый скрипт выполняет команды последовательно. Пустые строки и комментарии пропускаются. На экран выводятся и «ввод», и результат, что имитирует работу пользователя.

Ошибки внутри стартового скрипта отображаются, после чего выполнение продолжается.

Для демонстрации ошибки чтения конфигурации создан `config/broken.json`.

## Этап 3. VFS

Источник VFS — ZIP-архив.

После загрузки содержимое архива полностью переносится в память:

- файлы хранятся как `bytes`;
- каталоги — как нормализованные POSIX-пути;
- данные исходного ZIP не распаковываются на диск;
- `touch` и `rmdir` изменяют только состояние в памяти.

В `sample_vfs.zip` присутствуют:

- несколько файлов;
- бинарный файл;
- дерево каталогов глубиной более трёх уровней;
- пустой каталог для тестирования `rmdir`.

Команда:

```text
vfs-load путь
```

загружает новую VFS из ZIP прямо во время работы.

## Этап 4. Основные команды

### `ls [путь]`

Показывает файлы и каталоги VFS.

```text
ls
ls /home/student
```

### `cd [путь]`

Меняет текущий каталог VFS.

```text
cd /home/student
cd docs
cd ..
```

### `uname [-a]`

Без аргументов выводит имя реальной ОС, на которой запущен эмулятор.

`-a` выводит полную информацию `platform.uname()`.

### `cal`

Поддерживаются формы:

```text
cal
cal 2026
cal 10 2026
```

### `uptime`

Показывает время работы текущего процесса эмулятора.

## Этап 5. Дополнительные команды

### `touch путь`

Создаёт пустой файл в VFS. Изменение существует только в памяти.

```text
touch /new.txt
touch "file with spaces.txt"
```

### `rmdir путь`

Удаляет только пустой каталог.

Попытка удалить непустой каталог приводит к ошибке.

### `vfs-load путь`

Заменяет текущую VFS данными другого ZIP-архива.

## Обработка ошибок

Реализованы, в частности:

- неизвестная команда;
- неверное число аргументов;
- ошибка кавычек при разборе;
- переход в отсутствующий каталог;
- попытка удалить непустой каталог;
- неверные параметры `cal`;
- отсутствие файла VFS;
- неверный ZIP;
- ошибка JSON;
- отсутствие стартового скрипта.

Пример:

```text
username@host:~$ unknown-command
error: unknown-command: неизвестная команда
```

## Автоматические тесты

15 проверок, включая ошибки JSON, приоритет CLI, продолжение скрипта после
ошибки, сохранение ZIP на диске и двоичных данных в памяти.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Тестируются:

- аргументы в кавычках;
- состояние `cd`;
- ошибка при `rmdir` непустого каталога;
- удаление пустого каталога;
- неизвестная команда;
- загрузка ZIP VFS.

## Что показать на защите

1. Запустить:

```bash

```

2. Обратить внимание на отладочный вывод итоговой конфигурации.
3. Показать `ls`, `cd`, переходы по вложенным каталогам.

6. Выполнить:

```text

```

9. Завершить:

```text

```

## Подготовка и сборка

Внешние зависимости не нужны. `run.sh` настраивает `PYTHONPATH` и создаёт
ZIP-архивы из текстовых JSON-манифестов в `vfs/`. Содержимое файлов в
манифестах закодировано base64. Архивы и кэш Python исключены из Git.

Отдельная подготовка данных:

```bash
python3 scripts/build_vfs.py
bash scripts/run_vfs_variants.sh
```

Варианты VFS: минимальный (пустой каталог), основной (текстовые и двоичные
файлы, дерево глубже трёх уровней), альтернативный (другое дерево).
`touch` требует существующий родительский каталог и сохраняет содержимое
существующего файла. `rmdir` не удаляет текущий каталог и его родителей.
